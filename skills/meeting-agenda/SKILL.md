# Meeting agenda

An agenda is a list of **outcomes**, not topics. Each item says what will exist when its **timebox** ends: a decision, a shortlist, a shared understanding.

## Gather
- Purpose, length, attendees and their roles, from the calendar invite if a calendar is connected.
- Open items from the last meeting's notes, if they exist.
- Decisions that are due, and who can make them.

## Steps
1. Write the purpose as "By the end we will have ___." If the blank can only be filled with "shared an update", recommend a written update instead and offer to draft it.
2. List the items. Tag each **Decide**, **Discuss** or **Inform**.
3. Move `Inform` items to pre-reads unless they need live questions.
4. Give each item an owner, a timebox and its outcome. For `Decide` items, name the decision-maker and the options on the table.
5. Order by importance: decisions first, while the room is fresh.
6. Reserve the last five minutes for decisions and actions read back.
7. Check the invite list: each attendee is needed for at least one item. Suggest the rest as optional.
8. List pre-reads with who must read them and by when.

## Shape
```
<Meeting name>, <date>, <length>
Purpose: By the end we will have <...>
Pre-reads: <document>, <who>, <by when>

| Time | Item | Type | Owner | Outcome |
| 0:00 | ...  | Decide | ... | Vendor chosen from A or B |
| 0:50 | Decisions and actions read back | | Chair | |
```

## Done when
- Timeboxes add up to the meeting length.
- Every item has an owner, a type and an outcome a note-taker could tick off.
- Every `Decide` item names who decides.
- The purpose sentence is filled with something other than an update.
