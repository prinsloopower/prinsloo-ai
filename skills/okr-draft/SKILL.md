# OKR draft

A key result is an **outcome**: a measure moving from one value to another. Work the team will do is an **output**, and it belongs in the initiatives list beneath.

## Gather
- The period, and the team or person the OKRs are for.
- Parent goals: company or department objectives to align to.
- Current numbers for anything that might become a key result.
- Last period's OKRs and scores, if there were any.

## Steps
1. Draft three to five **objectives**: qualitative, a direction a team would want to move in, achievable within the period. Link each to a parent goal.
2. Under each, draft two to four **key results** as "Move <measure> from <baseline> to <target> by <date>."
3. Apply the outcome test to every key result. "Launch the new onboarding flow" is an output: ask what result the launch should produce, write that as the key result, and move the launch to initiatives.
4. Give each key result an owner and a data source.
5. Label each one **committed** (expected at 1.0) or **stretch** (0.7 is a good result).
6. List initiatives beneath each objective: the work expected to move the key results.
7. Check the set: together, do the key results show the objective was met? Does any measure invite gaming, and what would balance it?
8. For a review of existing OKRs, show each rewrite beside the original with the reason.

## Shape
```
Objective 1: <direction>. Supports: <parent goal>
  KR1.1: <measure> from <x> to <y> by <date>. Owner. Source. Committed or stretch.
  Initiatives: <work>
```

## Done when
- Every key result has a baseline, a target, a date, an owner and a source, or a visible placeholder.
- Every key result names a measure. Deliverables sit under initiatives.
- There are at most five objectives and four key results each.
- Every objective links to a parent goal, or says it stands alone.
