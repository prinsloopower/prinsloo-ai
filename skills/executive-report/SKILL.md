# Executive report

Build a **pyramid**: the answer first, three supporting points beneath it, evidence beneath each. A reader can stop at any level and leave with a correct, shorter version.

## Gather
- The source material: data, status reports, analysis, earlier reports, from connected tools or supplied.
- The audience, and the decision or belief the report should produce.
- The previous report in the series, to keep measures comparable.
- `business-context.md`, if one is in the working folder, project or attachments: it sets voice, brand, products, customers and competitors.

Ask once, in one message, if the audience or the purpose is missing.

## Steps
1. Write the **bottom line** in two sentences: where things stand and what is recommended or asked.
2. Choose three supporting points. Ask "so what?" of each until it bears on the bottom line.
3. Back each point with evidence. Give every number a comparison: against plan, prior period or benchmark.
4. Put bad news in the first third of the page, together with the plan to deal with it.
5. List the top risks, each with a mitigation and an owner.
6. State the ask: the decision, resource or support needed and by when. If nothing is needed, write "No decision needed."
7. Move detail to an appendix. The main body holds one page.
8. Build it as a document with the session's document tools, Word or PDF if the user names one.

## Shape
```
<Title>, <period>, <author>
Bottom line
Why: three points, each with evidence
Risks and mitigations
What we need from you
Next milestones | milestone | date | owner |
Appendix
```

## Done when
- The bottom line stands alone as a correct summary.
- The main body is under 450 words.
- Every number has a comparison and a source, and matches the appendix.
- The ask is explicit.
- Every number, name and date traces to the inputs. A gap shows as a bracketed placeholder such as `[Q3 revenue?]`.
